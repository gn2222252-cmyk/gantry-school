### 為什麼機台程式跟平常看到的不一樣

因為機台的自動流程用**步進階梯圖（STL）**，不是一般的自保持階梯圖。兩種都是階梯圖，也都合法，差別在怎麼表達「先做 A 再做 B」：

| | 一般（自保持） | 步進（STL） |
| --- | --- | --- |
| 想法 | 用線圈記住狀態 | 程式本身就是流程圖 |
| 怎麼換步 | 下一步回頭切斷上一步 | `SET S` 自動切換 |
| 輸出怎麼關 | 要自己寫條件 | 離開這一步自動 OFF |
| 插入一步 | 前後都要改 | 只改一個跳轉 |
| 適合 | 簡單開關、自保持、互鎖 | 有先後順序的機台動作 |

這台機台兩種都有：P5、P6 流程用步進，P9 互鎖用一般階梯圖，這也是實務常見的搭配。不過有些工廠規定不准用 STL，全部用自保持或步序暫存器寫，所以兩種都要會。

### 剛開起來畫面不動，是正常的

**PLC 開機後停在 S0 待機，還沒回原點，所以什麼都不會動。** 這時作用中步序是 `[0]`，兩座龍門都不動。監看視窗上方的黃色提示列會告訴你下一步要做什麼。

不用開 LabVIEW，只用模擬器就能讓它動起來：

| 順序 | 按什麼 | 會看到 |
| --- | --- | --- |
| 1 | 確認上方按鈕顯示**暫停**，不是**繼續** | 掃描數字一直在跳 |
| 2 | 確認 **X13 沒勾**、**X10 有勾** | 沒有急停，在自動模式 |
| 3 | 按模擬器的 **原點** | M20 原點完成 ON、提示列變成「已回原點」。龍門本來就在原點時，S10～S13 一閃就過 |
| 4 | 按 **前輸送帶放工件** | 橘色工件出現 |
| 5 | 按模擬器的 **啟動** | 畫面跳到 P5，輸送帶轉，工件到右端後右龍門開始動 |

**如果「掃描」數字停住：** 你按過**暫停**或**走一個掃描**，程式和機台都停了。按**繼續**就恢復。

**如果按了都沒反應：** 看提示列。常見原因是暫停中、急停被勾選，或 X16 沒勾（手動模式）。

**P1 的 M8002 永遠不亮：** 它只在開機第一個掃描 ON，人眼看不到，不是壞掉。

## 第 1 課：PLC 只會做一件事——不停掃描

PLC 不是收到事件才反應，而是一直重複這個循環：

| 順序 | 做什麼 |
| --- | --- |
| 1 | **讀輸入**：把 X0～X17 拍一張照片存起來 |
| 2 | **執行程式**：從第一行跑到 END，全部用剛才的照片判斷 |
| 3 | **寫輸出**：把算出來的結果一次送到 Y0～Y17 |
| 4 | **處理通訊**：回應 LabVIEW |

一圈叫一個**掃描**，這個模擬器約 10 ms。兩個重要結論：

- **按鈕按下去，要等下一個掃描才看得到。**
- **同一個掃描內，上面算出的結果，下面馬上能用。** 所以程式順序有意義。

為什麼要這樣設計：

| 設計 | 好處 |
| --- | --- |
| 開始時把 X 拍成一張照片 | 一圈內輸入不變，前後判斷不會互相矛盾 |
| Y 算完才一起送出 | 機器不會看到算到一半的結果 |
| 每圈固定由上往下跑 | 行為可預測，看程式就知道結果 |

**「慢一圈」的影響：** 一行要用的資料如果在它下面才算出來，這一圈拿到的是舊值，下一圈才是新值。

| 情況 | 影響 |
| --- | --- |
| 平常 | 幾毫秒，人和氣缸都感覺不到，不用管 |
| **故意利用** | 舊值就是「上一圈的狀態」，可以比較現在和上一圈：抓按下瞬間、判斷步序有沒有變 |
| 要小心 | 比一圈還短的訊號可能看不到；換步瞬間新舊輸出可能重疊一圈 |

在這台機台上：P8 每圈最後把步序存到 D250，下一圈比較，步序一變就重新計時；P3 先算 M14 才清異常，所以按一次復歸不會同時清異常又回原點。

> 自己看：按**暫停**，看「掃描」數字停住。按**走一個掃描**，數字加 1。

## 第 2 課：梯形圖和指令表是同一件事

梯形圖左邊是電源、右邊是線圈，中間的接點串聯（AND）、並聯（OR）。GX Works2 畫的是圖，檔案裡存的是指令。

用 Y4（右氣缸下降）當例子，這是 P9 的實際程式：

```
LD   M54     自動要下降
OR   M74     或手動要下降        ←（自動 或 手動）
LD   X002    在前側
OR   X003    或在後側            ←（前側 或 後側）
ANB          把上面兩組串聯起來
ANI  Y003    而且「上升」沒在動作
ANI  M3      而且沒有異常
ANI  M2      而且沒有急停
OUT  Y004    以上都成立，Y4 ON
```

畫成圖：

```
 ──┬─[M54]─┬──┬─[X2]─┬──[/Y3]──[/M3]──[/M2]──(Y4)
   └─[M74]─┘  └─[X3]─┘
```

| 指令 | 意思 |
| --- | --- |
| `LD` | 一條新線路開始，接常開接點 |
| `LDI` | 一條新線路開始，接常閉接點 |
| `AND`／`ANI` | 串聯一個常開／常閉接點 |
| `OR`／`ORI` | 並聯一個常開／常閉接點 |
| `ANB`／`ORB` | 把前面兩組區塊串聯／並聯 |
| `OUT` | 條件成立就 ON，不成立就 OFF |
| `SET`／`RST` | 條件成立就鎖定 ON／鎖定 OFF，條件消失也不變 |
| `PLS` | 條件由 OFF 變 ON 時，輸出 ON 一個掃描 |
| `MOV` | 複製數值 |

> 自己看：左邊清單點 **P9**，往下找 `OUT Y004`。一邊按 Manual 頁的 **R Down**，一邊看 M74 變綠。

**OUT 和 SET 的差別** 最常考：OUT 像按住才亮的按鈕，SET 像按一下就一直亮的開關，要 RST 才關。吸盤用 SET，因為吸住後要一路帶過去；氣缸下降用 OUT，因為只在那一步需要。

## 第 3 課：步進（STL）——機器的動作清單

機器動作有先後，用 STL 寫最直覺：**一次只有一步作用，條件到了就跳下一步。**

右龍門放料這三步的實際程式：

```
STL  S25         第 25 步：下降放料
OUT  M54           這一步要做的事：下降
LD   X012          前進條件：下限到位
SET  S26           跳到下一步

STL  S26         第 26 步：釋放
RST  M55           吸盤關
OUT  T1 D101       開始計時
LD   T1            前進條件：時間到
SET  S27           跳到下一步

STL  S27         第 27 步：上升
OUT  M53           上升
LD   X011          前進條件：上限到位
SET  S28           跳到下一步
```

每一步都是同一個套路：**做什麼 → 等什麼 → 去哪裡。** 寫步進就是在填這張表。

- `SET S26` 會自動讓目前的 S25 關閉，所以同時只有一步作用。
- 離開一步時，那一步的 OUT 線圈自動 OFF，所以不用手動關。
- SET、RST 的東西不會自動還原，所以吸盤要到 S26 才 RST。
- 程式最後要有 `RET`，代表步進區結束。

兩座龍門同時動，是因為啟動時 `SET S20` 和 `SET S40` 一起做：兩條步進各走各的，互不等待。

> 自己看：速度選 **1/5**，畫面跟著選**右龍門**，放一個工件，看黃色橫條一步步往下走，對照機台畫面。

## 第 4 課：跟著一個工件走一圈

| 步 | 機台在做什麼 | 跳到下一步的條件 | 動作的輸出 |
| --- | --- | --- | --- |
| S20 等料 | 右龍門在前側等 | X4 有料、X2 在前側、X11 在上、沒有循環停止 | 無 |
| S21 下降取料 | 氣缸下降 | X12 下限 | Y4 |
| S22 吸附 | 吸盤開，等 0.5 秒 | T0 時間到 | Y5（SET） |
| S23 上升 | 帶工件上升 | X11 上限 | Y3 |
| S24 往後 | 橫軸往後 | X3 後側 | Y6 |
| S25 下降放料 | 放到後輸送帶上方 | X12 下限 | Y4 |
| S26 釋放 | 吸盤關，等 0.5 秒 | T1 時間到 | Y5（RST） |
| S27 上升 | 空手上升 | X11 上限 | Y3 |
| S28 回原點 | 回前側，計數加 1 | X2 前側 | Y7 |

工件接著被後輸送帶送到 X5，左龍門用 S40～S48 做一模一樣的事，方向相反。

**輸送帶什麼時候動？** 看 P9 開頭的 M52：自動運轉中，而且 X4、X5 沒料，而且兩座龍門都不在帶上作業。

> 自己看：開 **IO Monitor** 頁，按**走一個掃描**，看是哪一個 X 改變，下一步才跳過去。

## 第 5 課：為什麼程式分成 P1～P10

| 段 | 工作 | 為什麼這樣分 |
| --- | --- | --- |
| P2 | 把按鈕和 HMI 命令合併 | 後面只要看 M6、M7，不用管命令從哪來 |
| P3 | 判斷模式、急停、異常 | 安全放最前面 |
| P4～P6 | 步進，**只決定想做什麼** | 把結果寫到 M50～M65，不直接碰 Y |
| P7 | 手動命令，寫到 M70～M85 | 同上 |
| P8 | 監視逾時 | 動作卡住要報警 |
| P9 | **唯一驅動 Y 的地方** | 所有互鎖集中一處，不可能漏 |
| P10 | 指示燈、回報給 LabVIEW | 只讀不改 |

**P9 是這個程式最值得學的設計。** 同一個 Y 不能在兩個地方 OUT（雙線圈，後面的會蓋掉前面的），所以自動、手動都先寫到 M，最後才合併：

```
自動想做 M54 ─┐
              ├─ 加上互鎖 ─→ Y4
手動想做 M74 ─┘
```

這樣互鎖只寫一次，不管誰下命令都逃不掉。上位機也一樣：LabVIEW 只能寫 M100 這種命令，不能直接寫 Y，所以就算 LabVIEW 當掉，互鎖和急停還是有效。

## 第 6 課：按下 Start 之後發生什麼

這是 LabVIEW 和 PLC 怎麼合作的完整路徑：

| 順序 | 誰 | 做什麼 |
| --- | --- | --- |
| 1 | LabVIEW UI 迴圈 | `Cmd_Edges` 看到 Start 被按，把字串 `M01001` 放進佇列 |
| 2 | LabVIEW 通訊迴圈 | 取出字串，用 `BW` 指令透過 RS-485 送給 PLC |
| 3 | PLC 掃描結束 | 處理通訊，把 M100 寫成 ON |
| 4 | P2 | `LD M100` `OR X014` → `PLS M6`，然後 RST M100 |
| 5 | P3 | M6 且 自動模式 且 已原點 且 無異常 且 在 S0 → M16 ON |
| 6 | P4 | S0 裡 `LD M16` → SET M0、S20、S40 |
| 7 | P9 | M0 ON、沒料 → M52 ON → **Y2 輸送帶轉** |
| 8 | P10 | M200 ON |
| 9 | LabVIEW 通訊迴圈 | 下一圈讀回 M200，**Auto Running** 燈亮 |

第 4～8 步全部在**同一個掃描**內完成，因為它們在程式裡由上而下排列。

> 自己看：按**暫停**。按 `Main.vi` 的 **Start**，等一下。然後按一次**走一個掃描**，到 P3、P9 看 M16、M52 的變化。

## 第 7 課：從零開始怎麼寫

拿到一台新機台，照這個順序，不要一開始就畫梯形圖。

1. **寫動作流程**：用白話寫，「工件到了 → 下降 → 吸 → 上升 ...」。
2. **列 I/O 表**：每個感測器、按鈕一個 X，每個馬達、電磁閥、燈一個 Y。對應架構書第 3 節。
3. **定原點**：機台平常停在哪個狀態。對應第 4.2 節。
4. **列步序表**：每一步填「做什麼、等什麼、去哪裡」，就是第 4 課那張表。
5. **列異常**：每一步如果等不到怎麼辦。這台用逾時，異常碼分橫軸和氣缸。
6. **列互鎖**：什麼絕對不能同時發生。對應第 4.8 節。
7. **分配軟元件**：哪些 M、T、D 做什麼，先寫表再寫程式。
8. **寫程式**：手動和原點先做，確認每個輸出都對，再做自動。
9. **逐項測試**：每個異常都要實際觸發一次，不能只測正常流程。

**機台程式最多的不是正常流程，而是異常處理。** 這份程式 507 個指令裡，P5、P6 的自動流程只有 91 個，不到兩成，其餘都是模式、安全、手動、互鎖和監視。

### 練習 1：改吸附時間（不用改程式）

到 **Parameters** 頁把 Vacuum Time 改成 30，按 **Write**。在監看視窗看 S22 的 T0 現在值數到 30 才跳步。

### 練習 2：加一顆「有料指示燈」

Y16 是備用輸出，讓任一端有料時亮燈。打開 `ladder\GANTRY_PLC_source.il`，在 P10 的 `;# Y15` 那段後面加：

```
;# Y16 有料指示燈
LD X004
OR X005
OUT Y016
```

存檔、重建、重開模擬器，放工件看 Y16 亮不亮。IO Monitor 頁看得到。

### 練習 3：按停止時蜂鳴器響 1 秒

提示：用 T40 計時（`OUT T40 K10`），條件是「循環停止中」，再把 T40 還沒到的狀態並聯進 Y15。想想看為什麼不能再寫一個 `OUT Y015`。

<details>
<summary>參考答案</summary>

在 P10 找到 Y15 那段，改成：

```
LD M1
OUT T40 K10
LD M3
LD M1
ANI T40
ORB
OUT Y015
```

不能寫第二個 OUT Y015，因為雙線圈會讓前面那個失效。T40 不在註解表裡，建置會報錯，要到 `ladder\devices.py` 的 OTHER 表加一行。

</details>

### 練習 4：故意弄壞，看異常怎麼發生

在模擬器按 **X13** 急停，到 P3 看 M2、M3 怎麼變，再看 P9 每一條 Y 為什麼全部斷掉。放開後按 Reset，看 M3 什麼條件才清掉。

## 到實機怎麼看

GX Works2 有一樣的監看功能：連上 PLC 後用 **Online → Monitor → Start Monitoring**，接點一樣會變色。這個監看視窗就是在模擬那個畫面，所以在這裡看懂，到實機就看得懂。

想看 LabVIEW 怎麼寫，打開 `Main.vi` 按 **Ctrl+E** 看方塊圖，四個迴圈上方都有中文說明；`docs\Main_說明.md` 有每個 VI 的用途。
